# 早睡系统 — V4 最终方案设计报告

> 2026-07-25 | V4 (极简权限 + 系统日志读取 + 本地AI分析 + 纯本地)
> 目标：帮你从"2点睡、躺着刷手机"到"23点睡、放下手机"

---

## 一、核心设计原则

1. **最小权限** — 只读系统已有的日志和数据，不申请传感器/后台等敏感权限
2. **纯本地** — 不需要服务器，不需要云，数据只在手机上
3. **内置 AI 分析** — App 内部调用手机的本地 AI 做分析，不是用 AI 来调 App
4. **语音打卡是特色，不是必须** — 能用 Siri/小爱一句话打卡更好，没有也不影响核心功能

---

## 二、数据来源（只读系统已有记录，不额外监听）

这是 V4 的核心变化：**不主动检测，而是事后读取系统已经记录的日志。**

### 2.1 各平台可读数据

| 数据类型 | iOS | Android | 鸿蒙 |
|---------|-----|---------|------|
| **📱 屏幕使用时间** | ✅ `ScreenTime API`（有限） | ✅ `UsageStatsManager` | ✅ 使用统计 |
| **🔓 解锁次数/时间** | ⚠️ 有限 | ✅ `UsageStats` 含解锁 | ✅ |
| **📊 App 使用时长** | ❌ 第三方不可读 | ✅ `queryUsageStats()` | ✅ |
| **😴 系统睡眠记录** | ✅ HealthKit | ✅ Health Connect | ✅ 运动健康 |
| **🌙 专注模式/睡眠模式** | ✅ `FocusStatus` | ✅ `NotificationManager` | ✅ |
| **📵 停用期（Downtime）** | ✅ ScreenTime API | ⚠️ 部分品牌 | ❌ |

### 2.2 核心思路

```
你打卡"我睡觉了"之后，系统不做什么特别的事。
第二天你打卡"我起床了"的时候，App 去读系统日志：

  · "昨晚 23:15 到 00:15 之间，手机有没有被用过？"
    → 读 UsageStats / ScreenTime
    → 如果有使用记录 → "宵禁违规"
    → 如果没有 → "宵禁达标 ✅"

  · "系统有没有昨晚的睡眠数据？"
    → 读 HealthKit / Health Connect
    → 有 → 显示深睡/浅睡时长
    → 没有 → 用就寝-起床时间估算
```

**等于说：App 只在你主动打卡的时候才读取数据，没有后台进程，没有持续监控。**

### 2.3 需要的权限

| 权限 | 用途 | 敏感度 | 可选？ |
|------|------|--------|--------|
| `UsageStats` / `ScreenTime` | 读取宵禁期间是否有用手机 | ⭐ 低（只读使用记录） | 核心功能 |
| HealthKit / Health Connect | 读取系统睡眠数据 | ⭐ 低（只读睡眠） | ✅ 可选 |
| 通知 | 到点提醒 | ⭐ 最低 | ✅ 可选 |
| 语音意图（Siri/App Actions） | 语音打卡 | 不需要额外权限 | ✅ 可选 |

**不需要的权限（V3 有，V4 删了）：**
- ❌ 加速度计（传感器权限敏感）
- ❌ 光线传感器（没必要）
- ❌ 后台 Service（用完即走）
- ❌ 定位（完全无关）
- ❌ 麦克风（不需要录音）

## 三、🎤 语音打卡（保留的特色功能）

### 3.1 实现方式与限制

#### iOS — Siri Shortcuts

```
实现方式：
  · Intents Extension — 自定义意图
  · 用户说 "Hey Siri，我睡觉了" → Siri 处理 → 调起 App 后台记录

限制：
  ✅ Siri Shortcuts 很成熟，一句话调起没问题
  ✅ 可创建多个备选短语（"我睡了"、"晚安"、"记录睡觉"）
  ⚠️ 第一次需要用户手动添加 Shortcut（或者 App 引导设置）
  ❌ 如果用户完全不用 Siri，这个功能就无效
  
最佳做法：
  App 首次启动时，引导用户添加 2 个快捷指令：
  "Hey Siri，我睡觉了" → 记录就寝
  "Hey Siri，我起床了" → 记录起床
```

#### Android — App Actions + 各品牌助手

```
通用方案（所有 Android 通用）：
  · actions.xml 声明 intent
  · Google Assistant / 系统搜索可识别
  · "OK Google, log my bedtime"

品牌专用（更深度）：
  · 小米小爱：小爱技能接入 → "小爱同学，记录睡觉"
  · OPPO 小布：小布技能接入
  · 限制：需要品牌开发者资质审核，不一定所有账号都能过

稳妥方案：
  先用 Android 通用的 App Actions（零审核，全平台）
  品牌专用技能作为后期优化项
```

#### 鸿蒙 — 小艺意图

```
  · Intent Framework 接入
  · "小艺小艺，我要睡了"
  · 鸿蒙 5.0+ 支持较完善
```

### 3.2 没有语音也不影响

语音是快捷入口，不是核心功能。App 里一样有按钮可以点：

```
没有语音 → 打开 App → 点"🌙 睡觉了" → 效果完全一样
有语音 → 直接说 → 不用打开 App → 更方便
```

## 四、📱 App 内置 AI 分析（核心功能）

这是你最初的想法：**App 内部调用手机本地 AI 来分析睡眠数据**，不是用外部 AI。

### 4.1 各平台的本地 AI 能力

#### iOS — Core ML + Create ML

```
iOS 自带 Core ML 框架，可以在设备上跑机器学习模型。

可行的分析用途：
  ① 趋势预测："按照你现在的趋势，下周能在 23:00 前睡吗？"
  ② 模式发现："你总是在周二熬夜"
  ③ 相关性："宵禁达标的日子里，心情评分高 0.8 分"
  
实现方式：
  · Create ML 训练一个简单的时间序列模型
  · 或使用 iOS 16+ 的 Tabular Regression 框架
  · 数据不需要离开手机，全部在 Core ML 里跑
```

#### Android — ML Kit + TensorFlow Lite

```
Google ML Kit 与 TensorFlow Lite Lite

可行的分析用途：同上
实现方式：
  · ML Kit 的表格数据推理
  · 或简单的线性回归（用 weka/自己实现）
  · 全部在设备端完成
```

#### 不依赖 ML 也能分析

实际上，**对于睡眠分析，简单的统计比机器学习更有用**。这些不需要任何 AI 框架：

```
① 移动平均线
  · 你过去 7 天平均几点睡？对比过去 3 天？
  · 直接代码算，不需要 ML

② 模式匹配
  · "你周二周四总是熬夜"→ 按星期几算平均值
  · "发工资前后睡得晚"→ 日期关联

③ 趋势
  · "比上周早了 22 分钟"→ 线性计算
  · "宵禁达标率提升了 15%"→ 比例计算

④ 建议
  · "你宵禁达标的日子平均多睡 52 分钟"
  · "最佳就寝时间是 22:45~23:15"
```

**结论：先用简单统计分析，后续需要时再加入 Core ML / ML Kit。**

### 4.2 分析结果展示

在 App 内直接展示，不需要去别处看：

```
你的 App 内有一个"分析"页：

📈 本周概览
  · 平均就寝：23:42
  · 宵禁达标率：5/7（71%）
  · 平均睡眠：7h12m

🔍 发现
  · 你周二周四总是睡得晚
  · 放下手机的夜晚，你多睡 40 分钟
  · 心情最好的是周六（睡了 8h）

💡 建议
  · 试试把宵禁目标从 23:00 调到 22:45
  · 你周二的睡眠最差，留意一下那天
```

❌ 没有 Telegram

## 六、技术架构

### 6.1 App 内架构

```
用户界面层 (React Native)
  ├── 首页（打卡、状态）
  ├── 日历（月度视图）
  ├── 分析（趋势、建议）
  └── 设置（目标、权限管理）
         │
数据层
  ├── 本地 SQLite（所有数据存这里）
  └── 系统数据读取器
       ├── UsageStats Reader (Android)
       ├── ScreenTime Reader (iOS)
       ├── HealthKit Reader (iOS)
       ├── Health Connect Reader (Android)
       └── 鸿蒙 Health Reader
         │
分析层 (全部在设备端运行)
  ├── 统计引擎（平均值、趋势、模式）
  ├── 规则引擎（建议生成）
  └── [可选] Core ML / ML Kit（深度分析）
         │
AI 助手接口 (可选)
  ├── Siri Shortcuts (iOS)
  ├── App Actions (Android)
  └── 小艺意图 (鸿蒙)
```

### 6.2 数据模型

```
用户设置：
  · 目标就寝时间
  · 目标起床时间
  · 宵禁窗口长度（默认 60 分钟）
  · 是否授权读取健康数据

打卡记录：
  · 日期
  · 就寝时间（手动或语音）
  · 起床时间（手动或语音）
  · 来源（手动/语音/Siri/小爱）
  · 宵禁结果（达标/违规/未知）
  · 心情（1-5）
  · 备注

系统数据（同步读取，不存储原始日志）：
  · 宵禁期间屏幕亮起次数
  · 宵禁期间最长使用时间
  · 宵禁期间使用的 App
  · 系统睡眠阶段（如已授权）
  · 实际睡眠时长

分析结果（本地计算）：
  · 每日/周/月统计
  · 趋势线
  · 模式发现
  · 建议列表
```

## 九、最终总结

```
一句话描述：
  一个只需要最小权限的手机 App。
  说一句"我睡觉了"就打卡，
  App 过一会儿自己去读系统日志看你有没有偷玩手机，
  然后每天早上告诉你：昨晚睡得咋样。

只需要这些权限：
  📊 手机使用统计（UsageStats）— 核心
  💤 健康数据（可选）— 增强
  
不需要的：
  ❌ 传感器  ❌ 后台服务  ❌ 定位
  ❌ 麦克风  ❌ 相机    ❌ 服务器
  
数据分析在哪跑：
  全部在手机本地。
  iOS 可以用 Core ML，Android 可以用 ML Kit，
  但就算没有这些，纯统计就够用了。
  
语音助手怎么用：
  你说 → Siri/小爱 → 记录打卡
  不是反过来。
```

## 一、核心设计理念

> **一个会自动锁住你刷的 App、监测你几点睡着、第二天告诉你"昨晚败在哪"、再用奖励和成就勾引你早睡的习惯养成系统。**

## 二、平台差异与技术方案

### 2.1 整体策略

不追求两个平台功能完全一致。**各平台用各自最擅长的方案，共享同一套产品逻辑。**

| 功能 | Android | iOS |
|------|---------|-----|
| 宵禁检测 | `UsageStatsManager` 精确读取 | `DeviceActivityReport` 系统渲染报告 |
| App 锁定 | 辅助功能权限（AccessibilityService） | `Shield API`（ManagedSettings） |
| 睡眠监测 | Health Connect + 可选加速度计 | HealthKit + 可选加速度计/麦克风 |
| 语音打卡 | App Actions / 小爱/小布 | Siri Shortcuts |
| 本地存储 | SQLite | SQLite |

### 2.2 iOS 深度方案

这是这次更新的核心——通过 iOS **已有的 API 合规地实现一切**，不需要任何私有 API。

#### ① 如何判断几点睡（三种策略组合）

```
策略一：HealthKit 睡眠数据（最推荐）
  · 系统自动记录或 Apple Watch 检测的睡眠
  · 直接读取 HKCategoryTypeIdentifier.sleepAnalysis
  · 用户授权一次，以后自动获取

策略二：手动"准备睡觉" + 传感器
  · 用户点"准备睡觉"后进入睡眠模式
  · 加速度计检测翻身频率 → 长时间不动 ≈ 入睡了
  · 可选：麦克风检测呼吸声（类似 Sleep Cycle，需隐私说明）
  · 不录音不上传，全部本地处理

策略三：DeviceActivityMonitor 熄屏检测
  · 监听最后一次锁屏时间
  · 长时间不亮屏 ≈ 入睡了
```

#### ② 如何分析睡前玩了什么 App

这是最大亮点：**用 iOS 的 DeviceActivityReport，既展示数据又不触碰隐私。**

```
你 App 里嵌入这样一个视图：

┌─────────────────────────────────────┐
│   📱 昨晚 22:00-02:00 的手机使用      │
│                                      │
│   ┌──────────────────────────────┐   │
│   │                               │   │
│   │   [系统渲染的饼图/排行榜]      │   │
│   │                               │   │
│   │   抖音       1h20m  ████████  │   │
│   │   微信        45m   ████      │   │
│   │   Safari      12m   █         │   │
│   │   小红书       8m   █         │   │
│   │                               │   │
│   └──────────────────────────────┘   │
│                                      │
│   数据来自 iOS 系统报告，App 拿不到    │
│   原始数据，只展示你看到了什么。        │
└─────────────────────────────────────┘

原理：
  · DeviceActivityReportScene 视图组件
  · 设定时间范围为"昨晚 22:00 到 02:00"
  · 系统自己绘制报告，App 进程不接触原始数据
  · App Store 审核完全合规
```

#### ③ 如何锁住成瘾 App

```
到 23:00，系统自动执行：

┌────────────────────┐
│  抖音               │
│                     │
│  ⚠️ 宵禁时间已到     │
│                     │
│  该睡觉了 💤         │
│                     │
│  [我知道了]          │
└────────────────────┘

  · Shield API（ManagedSettings 框架）
  · 把社交/娱乐/游戏 App 加入"屏蔽列表"
  · 到点自动遮罩，打不开
  · 用户可以去系统设置关掉，但多了一步操作
  · 增加"拿起手机的阻力"
```

#### ④ DeviceActivityEvent 超时提醒

```
用户设置：
  "如果在 23:00 后使用社交/娱乐 App 累计超过 30 分钟，通知我"

系统行为：
  → 23:00 开始计时
  → 用户刷了 30 分钟抖音
  → 系统事件触发 → App 收到回调 → 推送通知
  → "你已经在睡前刷了 30 分钟视频，该准备入睡了 🌙"
```

### 2.3 Android 方案

Android 没有 iOS 那么多限制，方案更直接：

```
宵禁检测：
  · UsageStatsManager.queryUsageStats(INTERVAL_DAILY, 宵禁开始时间, 起床时间)
  → 直接获取该时段内所有 App 使用记录
  → 精确到分钟级

App 锁定：
  · 利用"数字健康"API 或辅助功能权限
  · 或者引导用户使用系统自带的"专注模式"

睡眠数据：
  · Health Connect API（如用户授权）
  · 或者用加速度计本地估算
```

### 3.1 晨间"睡前习惯报告"（核心差异化功能）

每天早上用户点"我起床了"之后，系统生成一份**可交互的睡眠卡片**：

│                                           │

│  · 第二次 23:45（看了 8 分钟小红书）         │

**数据来源（iOS）：**
- 睡眠时间：HealthKit
- 宵禁检测：DeviceActivityReport + 屏幕状态
- App 使用排行：DeviceActivityReportScene（系统渲染）
- 建议：本地 AI 分析（基于历史模式）

### 3.2 宵禁"防沉迷"锁定

```
设定流程：
  ① 用户设置目标就寝时间（23:00）
  ② 设置"宵禁窗口"（默认 23:00~入睡）
  ③ 选择要屏蔽的 App 类别（社交/娱乐/游戏）

执行流程：
  ① 到 23:00 → 通知提醒 "该睡了"
  ② 可选：自动屏蔽选中的 App
  ③ 用户可以选择"再给我 15 分钟"（延长期）
  ④ 延长期结束后强制执行

解除条件：
  · 第二天早上 06:00 自动解除
  · 用户随时可以去系统设置关掉
  · 但多了一步操作 = 增加了"不自律的阻力"
```

| 🔥 | 白银作息 | 连续 14 天 | 解锁新主题 |
| 🔥 | 黄金作息 | 连续 21 天 | 自定义提醒语 |

- 奖励有实用价值（解锁新功能），不只是虚的

### 3.4 机器学习建议引擎

  · 宵禁达标记录

## 四、用户交互流程（完整版）

### 第一天

```
23:00 → 手机弹出通知：
        "🌙 该睡觉了。宵禁即将开始。"

23:00 ~ 23:10 → 用户做睡前准备
        · 手机会自动屏蔽抖音/游戏等 App（Shield API）
        · 用户打开 App，点"准备睡觉"
        · App 进入睡眠监测模式（加速度计监听）

23:10 ~ 入睡 → 系统监测中
        · 加速度计检测→用户逐渐安静→推断入睡
        · 如果中途拿起手机→记录宵禁违规
        · 手机自动进入"睡眠专注模式"

第二天 07:30 → 闹钟响 / 自然醒
        · 用户点"我起床了"
        · 系统从 HealthKit 读取睡眠数据
        · 查询 DeviceActivityReport（睡前 App 使用）
        · 生成"睡前习惯报告"
        · 展示连续天数 / 成就 / 宵禁达标情况
        · 用户评分心情

        → "恭喜！宵禁达标。你昨晚比上周这个时间早了 1 小时入睡。👍"
```

## 五、技术栈确认

### 移动端

| 层 | 选型 |
|----|------|
| 跨平台框架 | **React Native**（三平台共享 UI） |
| iOS 独有 | SiriKit Intents, HealthKit, DeviceActivity, ManagedSettings, Core ML |
| Android 独有 | UsageStatsManager, Health Connect, App Actions |
| 本地存储 | SQLite（react-native-sqlite-storage） |
| 图表 | victory-native / react-native-chart-kit |
| 状态管理 | Zustand |
| 导航 | React Navigation |

### iOS 扩展（单独的目标）

```
App 主 Target           DeviceActivity Monitor Extension
  │                              │
  ├── 打卡界面                    ├── 监听睡前 App 使用超时
  ├── 设置                        ├── 触发 Shield 屏蔽
  ├── 报告展示                     └── 记录熄屏/亮屏事件
  ├── 成就页
  └── 数据请求
        │
   DeviceActivity Report Extension
        │
    └── 渲染睡前 App 使用报告（饼图/排行）
```

### 不需要服务器

```
数据全程在手机上。
没有云同步，没有账号系统，没有后端。

App 即产品。
```
